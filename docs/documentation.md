# 工具文件與函式功能註解

## 維護範圍

每個已實作工具均須有 [文件索引](README.md) 中的獨立說明入口。共用機制可交叉連結，但工具本身應能讓讀者知道其用途、輸入、輸出、操作及限制。未實作能力只記錄狀態，不能提供虛構的可用 API。

共用文件只描述跨領域介面與責任；領域專用契約、資料、情境、弱點映射、使用方式及稽核紀錄放在 `domains/<domain>/docs/`，由共用索引連入。安全分類的標準版本與領域映射分開記錄，不把某個領域或 `designed` 狀態宣稱為通用已實作能力。

每個具名 `def`、`async def`、方法及巢狀函式均以 docstring 說明功能，包括測試 fixture、測試函式及輔助程式。簡短 helper 可用一句具體用途；複雜公開函式應再描述必要輸入、回傳、例外及副作用。lambda 的用途由周邊功能註解交代。

一般說明使用繁體中文；供 LLM 讀取的工具 docstring 可以保留英文，避免文件整理改變模型可見的工具描述。已有功能說明不應只為統一語言而改寫。

## 說明怎麼寫比較好懂

先用白話說明「這個功能做什麼、使用者要準備什麼」，再用一個具體例子帶入欄位與規則。閱讀順序由用途、例子到程式細節，讓第一次接觸專案的人也能看懂。

- 專有名詞第一次出現時，加上簡短中文解釋，例如 provider 是「負責拿取安全檢查結果的函式」。
- 程式名稱、欄位名稱與可用選項保留原文，例如 `source_id`，旁邊解釋它表示「哪個檢查工具提供結果」。
- 總覽先呈現主要步驟；時間限制、快取與錯誤分支放到對應的詳細說明。
- 白話說明仍須符合實際功能，不把未實作能力寫成已可使用；供模型讀取的工具 docstring 與提示不因改寫說明而變更。

## 每份工具文件的內容

1. 功能、責任與目前實作範圍。
2. 輸入／輸出型別、設定及產物位置。
3. CLI 或 Python API 範例，交代預設是否停用及所需前提。
4. 錯誤處理、生命週期、資料或請求隔離與外部依賴。
5. 驗證方法及實測的界線；假模型結果與真模型結果分開。
6. 直接使用套件／模型的授權及共用詳細表連結；採用和僅參考分開。

版本、來源 hash、模型 digest 或函式行為改變時，範例與限制也應同步更新。可執行指令應能對應現有 parser，不以草稿欄位代替實際設定。

## 文件檢查工具

在專案根目錄執行：

```powershell
.\.venv\Scripts\python.exe tools/check_documentation.py
```

工具僅使用 Python 標準庫，讀取本機檔案，不匯入專案模組、不安裝套件、不連線網路，也不啟動模型。它檢查：

- `src/deception/`、`mirage_validator/`、`tests/`、`tools/` 的 Python 語法及具名函式 docstring。
- 已登錄工具的程式位置與非空說明文件是否存在。
- `src/deception/` 新增的頂層工具目錄是否有文件登錄。
- `docs/` 與 `domains/` Markdown 文件的本地檔案連結是否指向存在的檔案。

有缺漏時列出檔案、行號或文件位置並以狀態碼 1 結束；全部通過時顯示函式及文件數量，狀態碼為 0。Markdown anchor 與外部網址的可用性、註解內容是否精確、範例是否真的符合業務語意，仍須人工核對。

檢查器自己的功能見 `main`、`check_functions`、`check_guides` 及 `check_links` 的註解。新增工具須同步更新檢查器的 `GUIDES` 對應及索引；這項登錄不能代替真正撰寫說明。

## 授權與驗證界線

此工具只使用 Python 標準庫的 `ast`、`pathlib`、`re`、`sys`、`urllib.parse`，隨 Python 的 PSF 授權及聲明管理，沒有新增套件。

文件檢查通過表示具名函式具有非空功能說明、文件登錄與本地連結完整，不表示執行功能已通過 API 契約、業務一致性或真模型品質驗證。可執行行為變更仍按各工具文件執行對應測試。
